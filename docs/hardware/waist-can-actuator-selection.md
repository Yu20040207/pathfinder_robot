# 腰部折叠舵机与 CAN 通信选型记录

状态：候选方案，尚未采购或进行实机验证（2026-10-13）。

## 目标架构

- 开发时：Ubuntu 电脑 → USB-CAN 适配器 → 一台 CAN 舵机；依次验证六台并设置唯一设备 ID。
- 运行时：Jetson/电脑通过 ROS 2 向 ESP32-S3 下发目标；ESP32-S3 的 TWAI 控制器 → 3.3 V 兼容 CAN 收发器 → CAN-H/CAN-L 总线 → 六台舵机。USB-CAN 适配器不需要永久装车，留作诊断工具。
- 舵机动力电源独立于 ESP32-S3 的 3.3 V 电源；CAN 总线仅在两个物理末端各设 120 Ω 终端电阻。非隔离收发器的参考地按设备说明连接；整机建议评估带独立隔离电源的隔离 CAN 模块。

## 卖家提供的《CAN协议.pdf》摘录与疑点

原件保留在本机 `/home/manbaout/下载/CAN协议.pdf`，未确认其再分发许可，因此本仓库仅记录接口摘要，不随源码上传原 PDF。协议首页称 ASMG-MD；标注 250 kbit/s、CAN 扩展数据帧、主机 ID `0x18EF0201`。数据区首字节为舵机 ID，第二字节为指令；`0x01` 设置位置/速度，`0x02` 读当前位置及目标位置，`0x07` 读当前位置及电流。文档将 `0xFE` 用作广播 ID，并明确禁止在多机总线上使用广播读取/修改 ID 指令。

尚待卖家确认：实际舵机型号、CAN-H/CAN-L 与供电针脚、默认舵机 ID、返回帧的仲裁 ID、16 位位置数值到角度的换算及大小端、速度数值实际单位、电流/扭矩连续额定值、断电保持方式、失联保护。协议中读取设置电流请求为 `0x04`，所示响应指令却为 `0x03`，需核对。

## 验证顺序与安全边界

1. 单机台架：核对接线和电源，在机械负载脱开且运动范围清空时先查询位置/状态，再低速小角度试动。
2. 逐台配置唯一 ID，逐台复测；最后才把六台挂上同一总线，确认回复无冲突和超时恢复。
3. 实测最不利折叠姿态扭矩、连续温升、总电流、机构限位及断电制动；不能把商品页的“最大扭矩”当成长期工作扭矩。结构转轴须独立承重，不能让舵机输出轴单独承受腰部弯矩。
4. 确认急停和掉电时腰部不会意外下落，之后再允许安装上半身负载。
