## 1. 现有可复用资产

| 资产 | 位置 | 跟随里的作用 |
| --- | --- | --- |
| 前后双雷达 360°（`/scan_merged`） | 已在跑 | **只做避障**（用户 2026-11-21 定）；可选兜底找目标（P2、默认关） |
| 人脸引擎（YuNet + SFace ONNX） | `fwr_vision` | 身份确认 / 重新锚定 |
| 考勤人脸库 | `fwr_attendance` sqlite | 办公室熟人可直接"验证身份跟随" |
| HP60C 深度 | `/robot/camera/*` | 近距人脸、身高/体型门控 |
| 安全链 | `collision_monitor` → `directional_safety_selector` → `base_bridge` | 跟随时唯一的减速/停止通路 |
| 速度约束 | `velocity_smoother max_velocity [0.20, 0, 1.0]`、`max_accel [0.35, 0, 4.0]` | 跟随速度天然被限在 0.20 |

**缺口**：一只**广角**前视相机 —— 但**不需要再买一只深度相机**（2026-11-21 用户质疑后修正）。

理由：跟随需要的三样东西，几何已经由双雷达提供，深度不是必需品：

| 跟随需要 | 谁提供 | 深度相机是否必需 |
| --- | --- | --- |
| 人的位置 (x, y) | **双雷达 360°，360° 无死角** | ❌ 不用 |
| 距离保持 0.9 m | 同上（雷达测距 ±2 cm） | ❌ 不用 |
| "簇上面是不是人" | RGB 人体检测框 + 雷达方位对齐 | ❌ 不用（近距离可用 HP60C 深度增强） |
| 身份/外观 | 广角 RGB | ❌ 不用 |
| 人脸确认 | **现有 HP60C** | 已有 |

所以最小增量是**一只 120° 广角 RGB（¥100~200）**，不是第二只深度相机。
HP60C 继续负责近距离人脸与刷脸考勤，位置不动。

> 第二只深度相机只在下列场景才值回票价：全黑/强逆光、需要精确 3D 人体姿态、
> 要在人侧后方绕行时判断髋部宽度。办公室日间用不到。

## 2. 系统架构（2026-11-21 用户定案：**相机主跟踪，雷达只避障**）

> 用户判断："用激光雷达做轨迹跟随太复杂，直接拿两个摄像头框住人体跟随，激光雷达只管避障。"
> **采纳。** 雷达腿部跟踪（聚类 + 双腿配对 + 关联）从主链路移除，改由 RGB 检测框 + 深度测距给目标，
> 雷达退回它最擅长的事：**安全避障 + 可选兜底**。

```
手机页面「跟随这个人」（点选/停止）
        │
广角 RGB ──► person_detector（YOLO11n/416，cv2.dnn，15 Hz）
        │            │ 人体框
        │            ▼
        ├──► target_tracker ──► 目标：方位 bearing + 距离 d + 外观特征 + 轨迹 ID
        │     （IoU + 外观 + 深度）
HP60C 深度 ──► depth_probe（框内深度中位数 → d；无效时用框高估距）
HP60C RGB  ──► face_id（SFace 身份确认/重锚定）
        │
        └──► follow_fusion（状态机 + 门控）──► /follow/target_pose
                                                     │
                                            follow_controller (20 Hz)
                                                     │ /cmd_vel_auto_unchecked
                     collision_monitor → directional_safety_selector → base_bridge
                                    （雷达只在这一层参与：避障/停车）
```

| 节点 | 输入 | 输出 | 频率 | 说明 |
| --- | --- | --- | --- | --- |
| `person_detector` | 广角 RGB | 人体框（可多人） | 15 Hz | YOLO11n ONNX 416×416，**`cv2.dnn` 现成，零新依赖** |
| `target_tracker` | 检测框 + 上一帧 | 目标 ID + bearing + 距离 | 15 Hz | 单目标：IoU 匹配 + 外观直方图，框丢了按速度外推 |
| `depth_probe` | HP60C 深度 + 目标框 | 距离 d | 15 Hz | 框内有效深度中位数；有效像素 <30% → 用框高估距 |
| `face_id` | HP60C RGB | 身份 + 相似度 | 5 Hz（按需） | 复用 `fwr_vision`（YuNet + SFace） |
| `follow_fusion` | 以上 + 手机选择 | `/follow/target_pose`、`/follow/state` | 15 Hz | 状态机 + 门控 + 迟滞 |
| `follow_controller` | `/follow/target_pose` | `/cmd_vel_auto_unchecked` | 20 Hz | 保持 0.9 m，输出仍被安全链约束 |

### 2.0 为什么这样更简单（用户判断成立）

| 对比项 | 雷达腿部跟踪（原方案） | 相机人体框（新方案） |
| --- | --- | --- |
| 人体判定 | 靠腿对几何猜，办公室里桌椅腿/垃圾桶天天假阳性 | **检测器直接说"这是人"** |
| 要调的参数 | 断点阈值、簇宽、腿间距、对称性、速度差…6~8 个 | 置信度阈值 + IoU 阈值，2 个 |
| 身份 | 雷达给不了，全靠人脸补 | **框自带外观**，人脸只做确认 |
| 距离 | 雷达精确（±2 cm） | 深度中位数（±5~10 cm），够用 |
| 遮挡 | 360° 不怕挡 | 会丢 1~2 s（见下） |
| 代价 | 办公室假阳性高、调参多 | **失去 360°，遮挡只能等** |

**新方案的三个已知短板与对策**（必须写进代码）：

| 短板 | 对策 |
| --- | --- |
| 人走出 ~90° 视场就丢 | 控制器**优先转向让目标回中**：bearing >25° 时先原地转、不前进 |
| 遮挡 1~2 s | tracker 按速度外推框；>2 s 转 LOST → 停车（绝不自动换人） |
| 深度在 60° FOV 外没数 | 回退"框高估距"：`d ≈ f_y × 1.70 / 框高像素`（人高按 1.70 m），误差 ±20%，0.9 m 目标够用 |

### 2.1 人体框跟踪怎么实现（算法与参数）

```
① 检测   广角 RGB → YOLO11n ONNX（416×416，只取 person 类 conf≥0.45，NMS 0.5）
         15 Hz；`cv2.dnn` 推理 ≈ 25~40 ms/帧（i5 单核 0.4~0.6 核）
② 关联   与上一帧目标框做 IoU 匹配（>0.3 视为同一人）+ 外观直方图相似度（>0.6）
         都不满足才认为目标丢失；多人时只跟"被锁定"的那一个，其余只做干扰项
③ 测距   三级优先：
         ① 深度中位数（框内有效像素 ≥30%，剔 0 / <0.3 m / >5 m / 空洞）；
            目标在 0.9~2.5 m 时最准（±5~10 cm）
         ② **脚点反投影**：框底边中点 (u, v_bottom) 反投影到地面平面 z=0
            → 得到人的落脚点 → 水平距离（**不依赖人高，俯角只影响精度一点，最抗相机高度变化**）
            要求：脚在画面内、相机外参已知、机器人所在平面近似平地
         ③ 框高估距 d ≈ f_y·1.70/框高（最后兜底，**俯角 >20° 时误差会到 ±30%，慎用**）
④ 方位   bearing = atan((框中心 x − 主点 x)/f_x) + 相机安装偏航
         目标点 = 车体系下 (d·cos(bearing), d·sin(bearing))
⑤ 外推   框丢失时按上一次速度外推 ≤0.6 s，同时把置信度打 0.3
⑥ 输出   /follow/target_pose = 目标点后方 0.9 m（沿 bearing 方向）
```

**模型与权重**：YOLO11n（或 YOLOv8n）导出 ONNX 放 `~/.local/share/four_wheel_robot/models/person_yolo11n.onnx`
（与现有 YuNet/SFace 同目录，`FWR_MODELS_DIR` 可覆盖）。**不需要装 ultralytics/onnxruntime**：
`cv2.dnn.readNetFromONNX` 已经在用（人脸那套就是），零新依赖。

**精度实算**：

| 距离 | 框高（1.7 m 人，f_y≈520 px@640×480） | 深度中位数 | 框高估距误差 |
| --- | --- | --- | --- |
| 0.9 m | ≈980 px | ±5 cm | ±10% |
| 2.0 m | ≈440 px | ±8 cm | ±15% |
| 3.0 m | ≈295 px | ±15 cm | ±20% |
| 4.5 m | ≈197 px | 深度开始飘 | ±25%（建议跟到 4 m 就够） |

> 结论：**跟随距离 ≤3 m 时，测距精度足够**（目标 0.9 m ±0.3 m 的死区本来就比误差宽）。

**办公室实测要盯的三个数**：检测框抖动（连续帧框中心位移的 std）、深度中位数跳变、丢框次数。

### 2.3 单帧处理伪代码（工程落地用）

```python
# ---- person_detector：15 Hz ----
frame = rgb (广角 1920x1080) -> resize 416x416
boxes = yolo11n.detect(frame, cls=person, conf>=0.45, nms=0.5)
boxes = [scale_back(b, 1920/416) for b in boxes]        # 换回原图坐标

# ---- target_tracker：锁定一个目标 ----
if locked is None:
    return                                              # 没锁定 → 不发目标
if not boxes:
    miss += 1
    pred = predict(locked, dt)                          # 按上次速度外推
    if miss * dt <= COAST_S (=0.6):                     # 外推期
        emit(pred, conf=0.3); state = COASTING
    else:
        state = LOST                                    # 停车 + 原地搜索
else:
    cand = max(boxes, key=lambda b: iou(b, predict(locked, dt)))
    if iou(cand, locked) > 0.3 and appearance_sim(cand) > 0.6:
        locked = cand; miss = 0; state = TRACKING
    else:
        miss += 1                                       # 不切换！只当没命中
        if miss * dt > COAST_S: state = LOST

# ---- depth_probe：测距 ----
depth_px = depth[box]                                   # HP60C 深度图对齐后
valid = depth_px[(depth_px > 0.3) & (depth_px < 5.0)]
if valid.size / depth_px.size >= 0.3:
    d = median(valid)                                   # 主方案
else:
    d = f_y * 1.70 / box_h                              # 兜底：框高估距
if abs(d - last_d) > 0.5 and valid_ratio < 0.5:         # 跳变保护
    d = f_y * 1.70 / box_h

# ---- 方位与目标点 ----
bearing = atan2(box.cx - cx0, f_x) + yaw_offset         # 车体系
target  = (d*cos(bearing), d*sin(bearing))              # base_link
bearing = ema(bearing, alpha=0.4)                       # 平滑（≈5 Hz 等效）
emit(back_off(target, follow_dist_m), conf)             # 人后方 follow_dist_m（头部 1.2）

# ---- follow_controller：20 Hz ----
if |bearing| > 25°:
    v = 0;  w = clamp(1.2*bearing, ±0.55)                # 先转，让人回中
else:
    v = clamp(0.8*(d - follow_dist_m), 0, 0.20)          # 距离环，限幅到导航同速
    w = clamp(1.2*bearing, ±0.55)
if d < follow_dist_m - 0.45: v = 0                      # 人停下/逼近 → 停
if front_clear < 0.50: v = 0                            # 净空门限（L1）
publish(v, w)   # 之后还有 directional_safety_selector + collision_monitor 两道
```

**关键点**：跟随时只用 `base_link` 相对量（bearing + d），**不依赖地图和 AMCL**——
所以跟随可以和导航互斥运行，不必为了跟人把 AMCL/Nav2 也拉起来。

## 3. 身份：不带标签怎么做到"不跟错"

### 3.1 两种选择模式

| 模式 | 适用 | 做法 |
| --- | --- | --- |
| **A. 验证身份跟随** | 已在考勤库里的同事 | 手机点「跟随我」→ SFace 比对通过（阈值 0.363）→ 绑定 `person_id` |
| **B. 临时锁定跟随** | 访客、未入库的人 | 手机实时画面上点选那个人 → 绑定**当前这条腿轨迹 + 外观特征**，不建人脸记录 |

办公室场景 **B 是主路径**（访客不用先录脸），A 作为熟人增强。B 不采集生物特征，合规压力小。

### 3.2 四重门控（候选必须全部通过才更新目标）

1. **轨迹连续性**：与上一帧目标框 IoU > 0.3；丢失后重检测必须落在预测框附近（±1.0 m）
2. **外观**：HSV 直方图相似度 > 0.6（光变剧烈时降到 0.4，靠轨迹兜住）
3. **体型**：框的"高宽比"与绑定值偏差 <25%；框高对应的估距与深度测距偏差 <30%
4. **人脸（若可见）**：SFace 身份一致 → 置信度 +0.2；**不一致只降级、不切换**（人转身后重锚定）

补充：
- 深度测距与框高估距**同时可用**时，两者偏差 >40% 判为可疑（说明框到的不是同一个人或多框粘连）
- 目标框面积突然缩小 >50% 且不连续（人的一部分被挡住）→ 置信度打 0.5，**不切换**

### 3.3 六条硬规则（决定"不跟错"的实际是这些）

```
① 选定即绑定：点选后锁定该轨迹 ID，不因"更像谁"而改绑
② 连续 0.8 s 一致才更新（8 帧 @10 Hz），单帧高相似度不切换
③ 丢失就停：原地等 2 s → 原地转动搜索 ≤5 s → 停车提示，绝不自动换人
④ 新目标必须人工确认：页面弹「发现相似目标，是否切换？」；未确认永不切换
⑤ 跟随时禁止"最近的人"策略：没有锁定目标时一律不出发
⑥ 每次切换/丢失写日志：时间、旧目标、候选、相似度、动作（商用可追溯）
```

## 4. 控制与避障

### 4.1 速度与距离（全部沿用已冻结值，不新增参数）

| 项 | 值 | 来源 |
| --- | --- | --- |
| 上限线速度 | **0.20 m/s** | `desired_linear_vel`（冻结） |
| 加速度上限 | 0.35 m/s² | `velocity_smoother.max_accel`（冻结） |
| 目标跟随距离 `follow_dist_m` | **头部 1.20 m** / 底盘 0.90 m，死区 ±0.20 m | 本方案（头部几何决定，见 §6.4） |
| 距离 <`follow_dist_m − 0.45` | 线速度 0 | 本方案（人停下/逼近时防撞） |
| 距离 >2.50 m | 全速 0.20 追 | 本方案 |
| 角速度上限 | 0.55 rad/s | `rotate_to_heading_angular_vel`（冻结） |
| 目标点 | 沿"人→机器人"方向退 0.9 m 的点 | 纯跟踪 |

### 4.2 三层避障（"随时避障"落地 —— 雷达只在这一层参与）

| 层 | 组件 | 作用 | 触发 |
| --- | --- | --- | --- |
| L1 | **跟随器净空门限** | 减速/停/禁止转向 | 前向 <0.70 m 持续 0.5 s → 减速 50%；<0.50 m → 停；侧向 <0.30 m → 禁止往该侧转 |
| L2 | **`directional_safety_selector`**（现有） | 左右扇区取更空旷一侧，ω 符号不符只归零转向 | 每帧 |
| L3 | **`collision_monitor_forward`**（现有） | 正面前停车框 0.32~0.38 m 硬停 | 每帧 |

L2/L3 是**现有导航共用的同一条链**，跟随模式复用而不旁路 —— 这意味着导航调过的安全参数在跟随里原样生效，不需要第二套。

> 被跟随的人本身会不会触发 L3？不会：目标距离 0.9 m，`front_stop` 框深 0.38 m；
> 只有当人主动逼近到 <0.6 m 时，L1 先停，L3 作为兜底。

### 4.3 绕行（v2，不在第一版）

办公室第一版用"减速/停/转向空旷侧"就够。若后续要**绕过障碍继续跟**：
把 `/follow/target_pose`（人后方 0.9 m）作为单点目标交给 Nav2 的 `NavigateToPose`，
规划器自然绕行；人在被跟随者自身的腿点云会挡住目标，需要把该腿簇从局部代价地图剔除
（`obstacle_layer` 的 `observation_persistence` 或独立的点云过滤），绕过后再切回直跟。
**第一版不做，避免和导航的 BT 抢控制权。**

## 5. 状态机

```
IDLE ──点选──► BINDING ──身份/轨迹确认──► FOLLOW
                  │失败                     │ 丢失 >0.5 s
                  ▼                         ▼
               IDLE（提示重选）           LOST ──2 s 等待 + 5 s 搜索──► 找到：FOLLOW
                                             └─ 找不到 ──► STOPPED（停车提示，等人工）
FOLLOW ──用户点停止 / 超时(30 min) / 距离 >6 m 持续 10 s──► STOPPED
```

| 状态 | 进入条件 | 退出条件 | 车的行为 |
| --- | --- | --- | --- |
| `IDLE` | 未选目标 | 手机点选 | 停 |
| `BINDING` | 收到点选 | 绑定成功（外观+体型记录） / 3 s 内没框到人 | 停 |
| `TRACKING` | 本帧命中且门控通过 | 连续 0.6 s 未命中 → `COASTING` | 跟随 |
| `COASTING` | 未命中 ≤0.6 s | 重新命中 → `TRACKING`；超时 → `LOST` | 停止前进，只保留转向 |
| `LOST` | 0.6 s 未命中 | 5 s 内找回 → `TRACKING`；超时 → `STOPPED` | 原地转搜索 ±30°，不动 |
| `STOPPED` | 搜索失败 / 用户停止 / 超时 / 距离>6 m 10 s | 人工重新点选 | 停 + 提示 |

任何时刻：`/follow/state` 回传手机（跟随中 / 短暂遮挡 / 已丢失 / 已停止），页面**必须显示当前绑定的人**（缩略图或编号），让人知道机器人认的是谁。

### 6.1 要买什么（修正后：不买第二只深度相机）

| 阶段 | 高度 | HP60C 俯角 | 广角机俯角 | 能做什么 / 不能做什么 |
| --- | --- | --- | --- | --- |
| **临时（底盘）** | 0.3~0.5 m | 仰视 15~30° | 仰视 5~10° | ✅ 跟人（腿部以上都在画面）、避障、链路联调；❌ **人脸识别基本不可用**（脸在 1.5 m，仰拍要 2 m 外才进画面）；❌ 家具遮挡多 |

| 项目 | 计算 | 结论 |
| --- | --- | --- |

### 6.4.1 两机位布局（头部，设计目标）

两只相机分工明确，**不要试图用一只兼两个角色** —— 人脸要"平视近处"，地面障碍要"俯视近场"，俯角要求相反。

| 机位 | 高度 | 俯角 | 水平视场 | 职责 |
| --- | --- | --- | --- | --- |
| **HP60C（身份机）** | 胸口 ≈**1.30~1.40 m**（沿用现有胸口安装） | **0~8°**（基本平视） | ~60° | 人脸比对（0.6~2.5 m）、考勤、跟随身份闸门 |
| **新广角 RGB（跟随机）** | 车头立柱 **1.10~1.20 m** | **15~20°** 俯视 | ~90° | 全身跟随、人体检测框、可选接低矮障碍 |

理由（几何算过）：

- HP60C 在 1.35 m 平视：人站在 1.0 m 时脸部在天顶角 +11°，2 m 时 +6° —— 都在 ±23° 垂直视场内，**0.6~2.5 m 都能拍脸**。
- 同一台机器若下俯 15° 去拍地面，1.0 m 处视线高度只有 0.8 m（拍胸不拍脸），**人脸比对会失效**。
- 新广角机俯 15~20° 后，地面 1.2~2.0 m 处进入画面，才能看到**低于雷达扫描面（75 mm）的障碍**。

安装注意：

- 立柱不得侵入上半身折叠轨迹；不遮挡 C1 雷达（雷达扫描面 75 mm，不冲突）
- 两机都加**手动可调俯角**（一位螺丝锁紧即可，¥0）—— 现场按实际身高微调
- 线束走车体内部并留应力释放，**USB 被拉脱一次就等于丢人**
- HP60C 外参（`base_link → camera`）**尚未标定**（`docs/hardware/hp60c-validation.md` 明确记着），
  深度要进代价地图前必须先补一个 static TF（卷尺量 x/y/z + 角度，±2 cm/±2° 足够）

### 6.4.2 ⚠️ 上半身是折叠机构 → 外参不是常数

用户 2026-11-21 确认：**上本身是折叠机构，两只相机都装头部**。这带来三个必须处理的问题：

| 问题 | 后果 | 处理 |
| --- | --- | --- |
| 头部高度/俯仰随折叠姿态变化 | 静态外参只在一种姿态下有效 | ✅ **已裁决（2026-11-21 用户）：行驶时上半身可以展开** → 运营工况只有"展开"一种，**只需一套标定** |
| 折叠过程中相机在动 | 跟随中出现"人突然跳位" | **折叠/展开动作过程中驻车**（订阅 `/torso/deployed` 或关节状态，变化 → 立即 STOPPED） |
| 与旧规则冲突 | 旧文档写"行驶时收拢" | 旧规则作废：跟随场景允许展开慢速行驶（0.20 m/s），前提见下 |

**展开行驶的安全前提（必须在实机验证前逐条打勾）**：

| # | 要求 | 为什么 |
| --- | --- | --- |
| 1 | 速度 ≤ **0.20 m/s**（沿用导航冻结值） | 重心更高，制动距离要留足 |
| 2 | 地面平整、无坡道 | 展开姿态侧倾余量小 |
| 3 | 展开/折叠**动作过程中必须驻车** | 相机在动 + 重心在移，不能边走边折 |
| 4 | 门洞/电梯/吊挂物通过性复核 | 头部 1.6 m，要确认无横杆、灯带、指示牌 |
| 5 | 外廓变宽要复核 `front_stop` 多边形 | 前停框只覆盖 ±0.22 m、深度 0.32~0.38 m，**且雷达只在 75 mm 高度**，看不到胸高障碍 |
| 6 | 机构刚度要够，相机不能抖 | 折叠件若有间隙，检测框会抖 → 测距抖动（见下） |

> **抖动提醒**：折叠机构若靠锁扣固定，展开后可能仍有 1~2° 的间隙晃动。
> 相机 1.6 m 高、目标 1.2 m 远时，1° 晃动 ≈ 2 cm 位移 → 框中心抖动 ~10 px。
> 处理：跟踪层已有 EMA（α=0.4）平滑；若实测抖动超 8 px，先加机械阻尼（橡胶垫/锁紧螺钉），
> **不要靠调算法掩盖**——抖动会让深度中位数和方位同时不准。

**推荐做法（成本最低、最稳）**：

1. **优先争取"头部装在刚性立柱上"** —— 折叠的是手臂/托架，头部高度不变。这样外参是常数，本方案零改动。
2. 若头部必然随折叠动：
   - URDF 加 `torso_fold_joint` + `head_link` + 两个相机 link；
   - 折叠只有两个稳定位（收拢/展开）时，**用限位开关/磁簧开关**输出 `/torso/deployed`，
     TF 在两套标定间切换（30 行代码，不需要编码器）；
   - 若有伺服/编码器反馈 → 直接发 `/joint_states`，TF 连续（更好）。
3. **跟随门控（硬规则）**：`deployed == false` → 拒绝开始跟随；跟随中变 false → 立即停车并提示。
4. 折叠全行程的**遮挡与线束干涉**必须实测（相机不能被自己的手臂挡住、线不能拉扯）。

### 6.5 相机几何必须参数化（换安装位置不改代码）

新建 `config/camera_mount.yaml`，**所有几何量只在这里出现一次**：

```yaml
hp60c:
  height_m: 1.50          # 相机光心离地高度（卷尺量）
  pitch_deg: 2.0          # 仰为正、俯为负（图纸/水平仪量）
  yaw_deg: 0.0            # 相对车头正前方
  x_m: 0.18               # 相对 base_link 前后
  y_m: 0.0
  fx: 0.0                 # 内参，由标定脚本写入
  fy: 0.0
  cx: 0.0
  cy: 0.0
wide_cam:
  height_m: 1.45
  pitch_deg: -15.0
  ...
```

**强制规则**：
1. 代码里**禁止硬编码**相机高度/俯角/焦距，全部读这个 YAML
2. 换安装位置 = 改 YAML + 跑一次标定脚本（内参用棋盘格，外参用卷尺 + 水平仪，±2 cm/±2° 足够避障用）
3. 目标框的**体型门控阈值**（高宽比）按安装位置分别标定，写在同一 YAML 的 `body_ratio`
4. 验收指标必须注明“在哪个安装高度测的”——底盘期测出的数字到头部要重测

> 为什么强调：俯角一变，`框高估距` 的误差从 ±15% 变 ±30%，体型门控阈值也会失准。
> 现在把高度写死，后期上头就得回来改代码，等于白做一遍。

### 6.6 上半身姿态：要不要再加一只 IMU？（2026-11-21 讨论）

**结论：先别买，而且定型舵机之后更不需要了。**（2026-11-21 用户给出型号：ASME-SD/B 型，
15 bit 磁编码器 = **32768/360° ≈ 0.011°/count**，协议与现有 ASMG-MD 一致、支持位置回读）

**头部姿态 = 底盘姿态（现有 IMU）⊕ 腰部关节角（舵机回读，0.011° 分辨率）**。
编码器精度已经比需求高两个数量级，**唯一的不确定项是机械背隙与结构柔性**。

**头部水平误差怎么算**（这三项加起来）：

| 误差源 | 典型值 | 能不能靠标定消掉 |
| --- | --- | --- |
| 底盘 IMU 的 pitch 精度 | ±0.3~0.5° | 静态零位可标；动态靠滤波 |
| 舵机位置回读精度 | **±0.011°**（15 bit，基本可忽略） | 可标 |
| 关节背隙 / 结构柔性 | **0.5~2°** | ❌ 消不掉，只能靠机械刚度 |

合计 **1~3°**。换成距离误差：1.2 m 处 1° ≈ 2 cm，3 m 处 ≈ 5 cm —— 在跟随的 0.9~1.2±0.3 m 死区面前可以忽略。

**所以不需要 IMU 的前提**：机构刚性好（锁扣/斜撑）、舵机有位置回读、调平精度要求 ≥2°。
**满足任一条就要加 IMU**：① 上半身有弹簧/拉索/薄壁打印件等柔性件；② 要求 ≤1°；
③ 要在行进中快速调平（>20 °/s）；④ 舵机最终型号没有位置回读。

**如果确实要买：买同款 DM-IMU-L1**（约 ¥200~400）

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **DM-IMU-L1（同款）** | 驱动 `fwr_imu` 已跑通、`yaw_scale` 标定流程现成、坐标系约定一致、by-id 即插 | 多根 USB 线、多一个 `ttyACM` |
| BNO085 / BMI270 模块 | ¥100~150，自带姿态融合，直接出 pitch/roll | **要新写驱动**，室内磁干扰下 9 轴融合反而添乱（只要 pitch/roll 时用 6 轴模式） |

> 第二只 IMU 装**头部支架刚性处**，与相机光轴对齐；frame_id 用 `imu_head`，
> `dm_imu_node` 起第二个实例（换 `serial_port` + `frame_id`）即可，**不用改驱动代码**。

### 6.6.0 定型舵机（ASME-SD/B）带来的三个额外收益

| 特性 | 对跟随/避障的价值 |
| --- | --- |
| **蜗轮蜗杆自锁** | 掉电不下垂 → 上半身姿态稳定、标定一次长期有效；CAN 断线也不会突然低头 |
| **15 bit 绝对编码器** | 上电即知角度（不用回零）；3 个关节角 + 连杆尺寸 → **头部姿态（含 yaw）完全可算**，不需要第二只 IMU |
| **0x07 可回读电流** | 舵机电流突增 = 上半身碰到东西了 → 可做**触碰检测**，补雷达/相机都看不到的"擦碰" |

**顺带：头部云台可以代替整车转向找目标**

舵机转速 **120°/s**（0.5 s/60°），是底盘转向（0.55 rad/s ≈ 31.5°/s）的近 4 倍。
所以可以：**头部先转头把目标拉回中间，头到限位（±60°）再让整车转**。
好处是底盘不必频繁左右摆，跟随更平滑；代价是要把关节角经 TF 折算到车体系（有回读，做得到）。
**这是 P2 优化项，P0 仍用整车转向。**

### 6.6.1 ⚠️ 跟随期间不要连续主动调平（重要）

调平会让相机持续微动 → 检测框抖 → 测距抖 → 控制器抽。正确做法：

```
起步前：调平一次（把头部相机俯仰校到标定值），记录腰部目标角
跟随中：腰部锁定在标定角，不动
       底盘 pitch/roll 由 IMU 读 → 在软件里补偿方位/高度，而不是去动舵机
需要调平：|pitch| > 5°（坡道、门槛）→ 先停车 → 调平（≤10°/s）→ 再继续
```

### 6.6.2 上半身避障（比调平更值得先做）

雷达只有 75 mm 高，看不见胸高障碍。**头部 HP60C 的深度通道正好补这块**：

| 项 | 值 |
| --- | --- |
| 检测窗口 | 前方 **0.4~2.0 m**、高度 **0.8~1.8 m**（车体系） |
| 判据 | 窗口内深度有效点 > **80 个**（约一个 20×20 cm 的物体）且最近距离 < 0.9 m |
| 动作 | 最近 <0.6 m → 停；0.6~0.9 m → 减速 50%；持续 1.5 s 仍有障碍 → 停车报警 |
| 频率 | 10 Hz 足够（深度 640×480 抽样 1/4） |
| 与安全链关系 | 作为**第 0 层**（最前面的软门限），最终仍由 `collision_monitor` 兜底 |
