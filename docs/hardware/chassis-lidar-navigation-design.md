# 二代底盘激光雷达与导航架构（设计阶段）

日期：2026-10-10；2026-10-12 更新样机雷达数量。目标是在室内平整地面上，为两驱差速底盘预留自主建图、定位与导航能力。本文件只确定架构和验收条件；雷达型号、精确安装尺寸及软件参数须在整机外廓确定后实测。

## 安装约束与布局

- 上半身可折叠、可运动，没有稳定的雷达安装位；折叠机构也会遮挡装在上半身的扫描视野。样机阶段先将**一只 2D 激光雷达固定在底盘前缘**，朝向底盘前方，且不随上半身运动。
- 上半身展开时不遮挡底盘雷达，这是机械设计和样机验收的约束；还须检查上半身运动的全过程。雷达扫描面、支架和线束不得与折叠机构、轮架及外壳干涉。
- 前置单雷达的实际覆盖范围取决于型号视角、安装位置及底盘遮挡；**不把它视为机器人周围 360° 无盲区感知**。重点检查前方、左右斜前方、贴近车体及侧后方盲区。样机实测后，再决定是否增加后置雷达。
- 安装高度由需要识别的障碍物、底盘遮挡和折叠机构最低位置共同确定；不在缺少外廓尺寸时指定数值。单层 2D 扫描无法覆盖低于扫描面或悬空伸入路径的全部障碍，后续按场景评估补充传感器。

2026-10-12 URDF 示意采用 **RPLIDAR C1 候选型号**：`laser_front` 通过固定关节连接 `base_link`，底盘 +X 为前，示意坐标为 `xyz=(0.19, 0, 0.2298) m`，姿态为水平、朝前。雷达示意外廓按[思岚 C1 机械图](https://d229kd5ey79jzj.cloudfront.net/3157/SLAMTEC_rplidar_datasheet_C1_v1.0_en.pdf)约 55.6×55.6×41.3 mm 绘制，扫描面按图示底面以上约 29.8 mm 放置；可视化外形简化为方形底座和圆柱光学罩，**不是精确 CAD**。底面暂放在示意底盘顶面 `z=0.20 m`；安装位置和底盘仍是占位，购买后要按实物重新测量固定孔位、扫描平面高度、线束及上半身全行程遮挡。前置安装会保留机身后方盲区，不据此启用自主倒车。

2026-10-22 实物测量已替换上述示意位置：扫描中心距 520 mm 长底盘的最前沿向后 50 mm，即相对几何中心前方 210 mm；左右居中、离地 75 mm。雷达扫描零方向的 180° 修正保持。外壳高度和遮挡范围仍需现场扫描验证。

## ROS 2 数据与导航链路

2026-10-12 确认样机先使用现有 ESP32-S3 控制板，不等待 STM32。用户现指定后续使用 **DM-IMU-L1 成品六轴 IMU**。该成品模块的主机侧接法优先评估 USB；若最终选 CAN 或 RS485，则根据实物协议和线束设计决定由 ROS 2 主机还是 ESP32-S3 读取。ESP32-S3 仍负责左右轮编码器采样、底盘速度闭环和故障停车，主机负责轮式里程计与 IMU 融合。接线方式、电源、输出频率和数据帧以到货固件版本的官方手册实测确认，不能沿用原先对裸 BMI088 的 SPI 接线假设。

开发阶段主机为当前 Ubuntu 电脑，后续目标为 Jetson Orin Nano Super Developer Kit（8GB）；主机迁移不改变上述 ROS 2 话题和底盘控制协议。若选用支持 USB 直连的成品 IMU，则由主机驱动读取，不必强制经 ESP32-S3。迁移要求见 [Jetson 主控迁移约束](jetson-migration.md)。

2026-10-13 实机 USB 只读检查：DM-IMU-L1 在 Ubuntu 枚举为 `/dev/serial/by-id/usb-DM-Tech_DM-IMU-L1_DMIMU20250212-if00`（当次为 `/dev/ttyACM1`），921600 波特率。连续 3 秒采得加速度、角速度、欧拉角和四元数各 2994 帧，约 998 Hz/类；11976 帧均通过 CRC16/CCITT-FALSE 校验。静置时角速度均值约 `(0.0022, 0.0026, -0.0003) rad/s`，加速度模长约 `9.776 m/s²`，四元数模长约 1。传感器当时倾斜放置，Roll 约 40°。这证明本机 USB 数据链路可用；尚未验证安装坐标、动态转向响应、ROS 2 节点或与轮式里程计融合。当前会话不在 `dialout` 组，临时 ACL 允许读取 `/dev/ttyACM1`，重插后需重新授予或将用户加入 `dialout` 并重新登录。

1. 前置雷达驱动发布带时间戳的 `sensor_msgs/LaserScan`，建议话题 `/scan_front`；具有固定的 `laser_front` 坐标系及到 `base_link` 的静态 TF。驱动还需提供失联/异常状态供运动安全逻辑使用。
2. 左右轮编码器生成连续的轮式里程计；IMU 固定在底盘刚性结构上，提供角速度等测量。经标定和融合后发布 `odom` 及 `odom→base_link`。IMU 不代替轮编码器，也不单独承担建图。
   - 实机增加独立的 DM-IMU-L1 驱动节点，发布带时间戳、协方差和 `imu_link` 坐标系的 `sensor_msgs/msg/Imu` 到 `/imu/data_raw`；安装位姿测量完成后，在机器人描述中添加固定的 `base_link→imu_link` TF。无硬件时不发布伪造 IMU 数据。
   - 由里程计融合节点订阅轮式里程计与 `/imu/data_raw`，只由一个节点发布 `odom→base_link`；先核对轴向、单位、零偏、时间戳和协方差，再启用融合。Gazebo 当前仍直接提供 `/odom` 和该 TF，并未接入 IMU。
3. 建图/定位链路先使用前置雷达扫描和里程计，提供 `map`、`map→odom`。若后续增加后置雷达，再验证所选 SLAM 软件的双路扫描接入方式。
4. Nav2 的障碍层先使用前置扫描作为 observation source，用于前方局部避障；全局地图与定位用于路径规划。在没有后方可靠感知和相应安全验证前，不启用自主倒车或需要后退的恢复动作。导航输出速度命令经过底盘安全层，再交给下位机速度闭环；通信超时、传感器故障与硬件急停均应能停车。
5. Nav2 footprint 依据机器人**行驶时可能达到的最大水平外廓**及安全余量确定。若上半身运动会改变外廓，需动态更新 footprint 和运动限制；在该能力完成验证前，行驶状态固定为上半身收拢，展开或动作时底盘驻车。

## 实施前测量与验收

- 测量底盘外廓、轮架/外壳位置、折叠机构全行程包络，以及机器人行驶姿态的最大外廓；据此确定雷达支架、扫描高度、电源和数据接口。
- 用扫描扇区图和 RViz 检查前置雷达的实际视野；把测试障碍物依次放在正前、左右斜前方、左右侧方及贴近车体的位置，记录可见范围、后方盲区与最低可探测障碍高度。未被稳定观测的区域不能作为自主行驶的安全覆盖区。
- 检查上半身收拢、展开和运动全过程的雷达遮挡、支架振动及线束干涉；验证扫描时间戳、TF、里程计和 IMU 坐标方向，再进行建图与定位调试。
- 在完成底盘急停、速度闭环、传感器故障停车和可行驶导航验收前，当前仓库的路径预览/运动演示不作为实机自主导航能力。
