## 工作原理与边界

C1 雷达提供原始 `/scan`。`scan_mapping_filter` 将车尾长期遮挡的原始 −90° 至 +90° 扇区置为 NaN，另发 `/scan_mapping` 给 SLAM Toolbox 和 Nav2 局部、全局代价图；该角度边界须在静止实测中复核。底盘雷达新鲜度门、方向选择器和两路 Collision Monitor 仍读原始 `/scan`。SLAM Toolbox 独占 `/map` 与 `map→odom`，前沿探索器只给 Nav2 发送已知空地中的目标。自动命令经前向或后向 Collision Monitor 和方向选择器后到达 `/cmd_vel_auto_safe`，底盘桥接只订阅这个安全出口；人工键盘另走 `/cmd_vel_manual`。原地转向须同时得到两路监控放行，任一路停车就归零。普通 Nav2 路径不允许倒车；车后遮挡长期存在，实车自动倒车保持关闭，未来增装后向超声波后再单独评估。

车后存在雷达盲区。`/scan_mapping` 被屏蔽的方向是未知区，不代表空地。过滤节点要求前左、正前、前右各 60° 扇区至少一半采样有效（含正常 `+Inf` 无回波）；低于此覆盖率时健康状态为假，自动运动预检拒绝放行。最近走过的路不是实时安全证明；人工键盘后退仍须有人持续目视车尾并能立即断开 12 V。禁止在有人可能突然进入、后方不可见或没有急停手段的场地启用倒车。不要把侧向扫描当作完整后向感知。首张实地图 `real_first_map` 含车体自回波造成的假障碍，仅留作诊断证据；重新建图并核对内部黑点前不用于自动导航验收。

## 分阶段验收

1. 静态链路：保持 `motion_enabled=false`，核对 `/scan`、`/imu/data`、`/odom`、`/map`、`map→odom→base_footprint→laser_front`、`/base/fault=0`、Nav2 action 与前后两个 Collision Monitor lifecycle 均为 active，并确认 `/cmd_vel_auto_safe` 仅由 `directional_safety_selector` 发布。注入断流和故障时桥接必须归零。
2. 仿真：在独立 `ROS_DOMAIN_ID` 和 `IGN_PARTITION` 下验证地图增长、目标稳定、障碍前停车与重规划、人工停止；测试完成后确认无剩余速度。仿真启动检查脚本：`python3 scripts/check_auto_mapping_sim.py --domain 98`。
3. 实车单个前进目标：封闭场地、有人看护，已验证单个静止纸箱近障停车；仍须验证动态障碍停车、持续带载直行与目标重规划。目标失败后不得反复冲撞。
4. 受限倒车：车尾全程可见，先单段不超过 0.10 m，再累计不超过 0.30 m。放入新障碍、雷达断流或人为停止时应立即停机；记录实际后退距离和 IMU 偏航。
5. 小范围自动探索：限定约 120 秒和封闭区，监控目标切换、局部路径、故障码、编码器和停车距离。检查地图墙线、门口、障碍形状和轨迹后再考虑扩大区域。

每一步失败都停止升级，保留日志。整机增重、换地面或改变外廓后重新测起步与停距。
