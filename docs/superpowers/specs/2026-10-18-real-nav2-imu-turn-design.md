# 实机 Nav2 与 IMU 定角转向设计

日期：2026-10-18

## 目标与现状

目标是在现有 ESP32-S3、D157B AT8236、双 MG513X 编码器电机、DM-IMU-L1 和 RPLIDAR C1 上接通实机 Nav2，并支持人工请求相对转向角度（例如左转 5°）。原地急转由两轮反向驱动；缓转由两轮同向差速驱动。方向约定为从上方看逆时针为正：左原地转时左轮后退、右轮前进；右原地转相反。

当前 `/imu/data` 约 100 Hz，能区分左右航向变化；轮编码器和 C1 激光雷达分别已有实机读取代码。现有 `/wheel/odom` 节点只读 ESP32 串口且未发布实机 `odom→base_footprint`。现有 Nav2 配置用于 Gazebo，使用仿真时钟；实机尚无地图。电脑已有 `nav2_bringup`、`slam_toolbox`，缺少 `robot_localization`。现有固件的通用 `v` 带载轮速控制未通过验收；2.5 kg 配重下左原地转曾在 75% PWM 时失速并锁定故障。因此可以先完成静止链路集成，不能直接开放自主行驶。

## 数据流与单一归属

```text
C1 /scan ────────────────→ slam_toolbox → /map, map→odom
                              ↓
                           Nav2 /cmd_vel ──┐
DM-IMU-L1 /imu/data ──┐                     │
                      ├→ 里程计融合 → /odom │
ESP32 编码器 ──┐       │                odom→base_footprint
              └→ 底盘桥接节点 ←───────────────┘
                     ↑ 人工 TurnRelative 动作，需与 Nav2 命令互斥
                     ↓ 串口命令 / 状态 / 故障
                   ESP32-S3 → 双电机
```

底盘桥接节点是 ESP32-S3 USB 串口的唯一长期持有者。它在打开时独占串口、核对固件握手，读取连续状态和原始编码器计数，发布带时间戳的轮式里程计、驱动轮 `/joint_states` 及底盘故障状态；它订阅 `/cmd_vel` 并发送轮速命令。现有 `wheel_odometry_node.py` 与 `bench.py` 不得与该节点同时打开串口，人工调试脚本只有在停止桥接节点后才能使用。串口断开或状态消息过期立即进入停机状态；重连不自动恢复运动。ESP32 固件继续保留 300 ms 无命令停机和故障锁定；上位机不能自动清除失速故障。

桥接节点将目标线速度 `v` 和角速度 `ω` 换算为左右轮线速度：`v_left = v - ω·track/2`、`v_right = v + ω·track/2`。轮距初值 0.263 m、轮周长初值 0.210 m、编码器每圈 1468 计数，均需地面标定。进入 Nav2 实机控制前，固件必须在实际负载下可靠跟踪前进、后退及双轮反向轮速；目前的 `t` 指令仅用于有界诊断，不能代替连续 `/cmd_vel` 控制。

## 姿态、地图与坐标系

URDF 保持 `base_footprint→base_link→laser_front/imu_link` 的固定关系。安装方向和高度须对照实物测量，尤其要复核 C1 扫描正前方与 `+X` 一致、IMU 正偏航与机器人左转一致。仅一个融合节点发布 `odom→base_footprint`；`robot_state_publisher` 发布固定 TF，并根据桥接节点的驱动轮 `/joint_states` 发布相应车轮 TF；没有传感器的万向轮转向角不伪造为实测值。在线 SLAM 发布 `map→odom`。不能以静态假 TF 代替定位链路。

轮编码器提供平面位移和轮速，IMU 角速度辅助航向。六轴 IMU 的绝对 yaw 会漂移，定角动作只使用短时间内的相对 yaw；融合前必须测量静止偏置、轴向、时间戳及协方差。实机节点统一 `use_sim_time: false`。先在电机停机且可推动底盘的条件下检查 `/scan`、`/imu/data`、`/wheel/odom`、TF 时序和方向，再用在线 SLAM 建立当前场地地图。建图完成后保存地图、检查占据栅格与实际障碍物一致，随后再选择实时 SLAM 导航或已保存地图定位。

实机 Nav2 使用独立参数文件和启动文件，不复用 Gazebo 的 `corridor_nav2.yaml`。障碍层以 C1 `/scan` 为输入，机器人 footprint 以实测最大行驶外廓加余量确定；目前 URDF 中的尺寸仅是预览值。前方传感器后侧受车体遮挡，在获得可靠后方感知和整车清障验证之前，自动导航禁止倒车及无人监督的原地旋转。早期 Nav2 测试只允许低速前进和缓转，且需人在场并保留立即断电手段。

## 定角急转与缓转

提供人工调用的 `TurnRelative` 动作，目标为有符号相对角度和模式 `pivot`（原地急转）或 `arc`（前进缓转）。动作启动前确认 Nav2 没有占用底盘；执行时拒绝新的 Nav2 速度命令，取消动作或异常退出立即停机。Nav2 的普通路径跟踪仍通过 `/cmd_vel`，不把每条 Nav2 角速度命令改写成离散定角动作。

动作以开始时的 IMU yaw 为零点，持续计算包角后的相对角度和角速度，并根据剩余角度减速、到达目标后主动发零速。`pivot` 使用左右轮反向轮速；`arc` 使用两轮同向、外侧轮较快且不命令倒车。初始角度误差验收目标为 ±2°，须经过重复地面试验后才视为可用。IMU 数据过期、编码器无进展、驱动故障、串口掉线、超过动作时间或检测到异常超调时，立即停机并报告失败；不得因“尚未达到 5°”而无上限继续加 PWM 或自动清故障。当前固件 0.5 秒 `t` 诊断及 60%–75% PWM 不是最终定角控制器。

## 分阶段验收与开放门槛

1. **静止联通**：串口唯一占用、固件握手、状态/故障解析、IMU 与雷达时间戳、TF 链和 `use_sim_time=false` 正确。注入 `/cmd_vel` 超时、IMU/雷达断流、串口断开、节点退出，确认桥接与固件最终输出均为零；此阶段不驱动地面机器人。
2. **定位与建图**：在电机停机状态下推动或受控移动底盘，确认轮里程计与 IMU 正负方向一致、`odom→base_footprint` 连续，完成真实场地的在线 SLAM 与地图保存。没有有效地图或定位时，Nav2 不发运动命令。
3. **带载底盘**：在 2.5 kg 当前配重下，悬空和地面分别检验双轮前进、后退、反向以及不同轮速；重复测试不得有失速、明显单侧停轮、供电重启或不受控偏航。左原地转在 75% PWM 下的失速必须查明并解决。最终整机质量增加后重新验收，不能沿用 2.5 kg 的结论。
4. **定角动作**：空旷场地分别重复验证 ±5° 的 `pivot`、`arc`，记录 IMU 目标误差、编码器位移、停止距离和失败率；角度误差和停机保护达标后才标记动作可用。
5. **Nav2 小范围运动**：先只允许低速前进与缓转，在可立即断电的场地验证一段短路径、障碍层更新、取消目标和传感器失联停机。逐步扩大范围。后方盲区处理完成前，保持自动倒车和无人监督急转关闭。

任何阶段失败都停止向下一阶段开放实机运动。软件故障保护不代替驱动电源开关或独立硬件急停。

## 实施边界

预计新增统一底盘桥接与仲裁节点、定角动作接口、实机里程计融合配置、实机 SLAM/Nav2 参数和启动文件，并扩展固件的带载轮速控制。改动须保留已有 Gazebo 演示和诊断脚本的可用性；实机与仿真配置分开。`robot_localization` 未安装，实施时需要补齐依赖。硬件侧待确认实际行驶外廓、IMU 安装位姿、雷达后方遮挡范围、配重与轮胎受力；这些数据影响安全参数和是否能开放自主旋转。
