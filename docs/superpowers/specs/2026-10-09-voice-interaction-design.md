# 四轮机器人语音交互系统设计

日期：2026-10-09（北京时间）

## 目标与边界

在开发电脑（Ubuntu、ROS 2 Humble）上先实现中文语音指令与自然对话，随后迁移到 Jetson。2026-10-12 用户确定目标型号为 Jetson Orin Nano Super Developer Kit（8GB）；迁移约束见 [Jetson 主控迁移约束](../../hardware/jetson-migration.md)。用户要求响应快、识别准确、调用成本低，并在断网时仍能听懂和执行基本指令。开放式对话可以依赖网络。

本阶段提供可运行的软件链路、模拟任务执行和可量化评测；不声称已有底盘实机控制。当前 `fwr_navigation` 仅发布规划路径，不发布 `/cmd_vel`，底盘驱动、急停反馈和 Nav2 尚未接入。语音模块不得直接发布 `/cmd_vel` 或绕过后续任务执行器。

## 方案选择

采用本地语音前端与云端文本大模型的混合方案。本地完成采音、唤醒/按键触发、语音活动检测（VAD）、中文语音识别（ASR）、基本指令判定和语音合成（TTS）。明确且受支持的基本指令完全在本地处理。开放对话和复杂意图在联网时调用云端轻量文本模型。所有模型通过适配接口接入，可在同一测试语料上替换比较。

全云端方案开发较快，但断网后基本指令不可用；全本地大模型方案避免按量收费，但在 Jetson 型号、内存和视觉负载未确定前无法保证速度。混合方案先满足可用性，再由测量结果决定是否迁移更多推理到 Jetson。

## 处理流程

1. `audio_capture` 从配置的麦克风采集单声道 PCM，记录时间戳和设备状态。初版支持按键触发；唤醒词作为可插拔前端，避免在麦克风和声学环境未定时依赖某个唤醒模型。
2. `vad` 检测话语边界，限制单次录音长度；播放 TTS 时默认暂停普通采音以避免自激，停止指令监听另行保留。
3. `asr` 输出最终文本及耗时、模型标识。首选本地 SenseVoice Small 建立中文基线；与 Paraformer 的中文专有名词/热词能力做同语料对比。初版不把模型自身置信度当作唯一安全判断。
4. `intent_router` 对文本做标准化，先匹配有限的本地指令表；未命中时且网络可用，调用云端 `dialogue_provider`。云端返回受约束的 JSON 意图或普通回答；解析失败视为对话失败，不猜测动作。
5. `task_gate` 校验动作类型、命名地点、参数范围、当前机器人状态和任务执行器是否就绪。需要移动的任务由独立任务接口接收；长时任务有接受、运行、完成、失败和取消状态。普通回答不经过动作通道。
6. `tts` 把确认、结果或对话回答播放出来。初版优先评测可在 x86_64 与 aarch64 使用的本地中文 TTS 后端；音色、速度和占用以实测选择。

优先级：物理急停及底盘安全控制最高；本地“停止/取消当前任务”高于对话和播报；机器人运动期间新的移动请求必须经任务状态检查。语音停止是软件任务取消，不代替物理急停。

## ROS 2 边界与数据契约

新增 `fwr_voice` 包负责语音流水线与纯 Python 适配接口，`fwr_interfaces` 增加语音与任务数据类型；`fwr_bringup` 增加语音配置和启动文件。音频设备、ASR、TTS、云端模型均在 ROS 2 适配层之外，便于电脑到 Jetson 的迁移。

拟定义如下接口，具体字段在实施计划中固定：

| 接口 | 用途 | 约束 |
| --- | --- | --- |
| `/robot/voice/transcript`，消息 | 最终识别文本、时间戳、来源、处理耗时 | 不携带原始音频；仅供观察与调试 |
| `/robot/voice/response`，消息 | 文本回答、播报状态、错误码 | 对话输出不能被其他节点解释为运动命令 |
| `/robot/task/execute`，Action | 接收经过校验的有限任务并返回状态 | 初版仅接模拟执行器；未来绑定导航/机械臂任务执行器 |
| `/robot/task/execute` 的 Action 取消请求 | 取消当前任务 | 本地停止词优先触发；失败应反馈 |

任务枚举初版为 `STOP`、`QUERY_STATUS`、`GO_TO_NAMED_LOCATION`。`GO_TO_NAMED_LOCATION` 只接受配置文件中的地点 ID，不接受大模型给出的坐标、速度或任意 ROS 话题名。没有实机任务执行器时，移动请求只在模拟器中执行，并明确播报“当前为模拟模式”。后续如需打卡查询、机械臂或电梯任务，各自增加经过审查的任务类型和执行器。

## 供应商与模型策略

ASR 的首轮候选为本地 SenseVoice Small 和 Paraformer；按相同录音、相同硬件比较中文字符错误率、机器人地点/人名召回率、话语结束到文本返回的延迟、CPU/GPU/内存占用。若本地性能不满足指标，可把云端实时 ASR 作为联网时的可选后端，断网仍回退本地。

文本大模型使用供应商无关的 `DialogueProvider`，只传转写文本、允许的任务清单和最少的状态摘要。首轮候选为低价、低延迟的中文文本模型；不在设计中锁定某家供应商或动态价格。每次调用设置超时、输出长度上限和费用/调用次数统计。敏感音频默认不上传；若以后启用云端 ASR，应明确提示和配置。

TTS 与唤醒词选型也经过本机与 Jetson 目标设备测量；不能仅因模型提供 aarch64 包就认定与视觉节点同时运行时满足实时性。模型文件、API 密钥和音频记录均放在仓库外；密钥从环境或受保护配置读取。

## 降级与异常

- 断网或云端超时：本地基本指令继续工作；开放对话播报简短离线提示，不重放过期请求。
- ASR 无文本、含糊或地点不在白名单：请求用户重说或确认，不执行动作。
- TTS 失败：文字状态仍可通过 ROS 2 观察；不影响停止指令。
- 任务执行器缺失、繁忙或返回失败：拒绝或反馈当前状态，不将大模型输出转成低层控制量。
- 输入/输出日志默认只存事件、耗时和错误码；录音与全文日志需显式开启并设置保留期限。

## 开发与迁移

电脑阶段先提供可注入的录音文件和文本输入，使语音链路无需麦克风、网络或底盘也能回归测试；再接真实麦克风、扬声器和云端模型。模拟任务执行器验证任务状态、取消和离线降级。最后在 Jetson 上替换音频设备名、推理运行时和参数配置，保持 ROS 2 消息及任务接口不变。设备到位后做内存、热功耗及视觉/语音并发压力测试。

## 验收指标

以下是首版设计目标，须在同一批机器人现场录音上实测，不是对模型性能的预先保证：

- 收集至少 100 条中文话语，覆盖安静/噪声、近讲/实际安装距离、不同说话人、地点名和停止指令；标注参考文本与期望意图。
- 离线基本指令意图准确率目标 ≥ 95%；“停止”漏检为 0/测试集，误触发单独记录。样本量扩大后再评估可靠性。
- 话语结束到本地指令确认的 P50 目标 ≤ 1 秒、P95 目标 ≤ 2 秒；联网普通对话首句播报 P95 目标 ≤ 4 秒。用端到端时间戳测量，未达标则针对瓶颈调整模型和触发方式。
- ASR 报告中文字符错误率及专有名词召回率，不用单一“识别率”概括；不同模型使用相同音频集比较。
- 报告每 1000 次对话的实际云端调用费用、平均音频时长、输入/输出 token 和失败率；把免费额度与促销价排除在长期成本预算之外。
- 连续运行 2 小时无音频设备丢失或不可恢复的语音节点故障；断网和恢复各进行一次完整测试。

## 待定硬件参数

Jetson 目标型号已定为 Orin Nano Super Developer Kit（8GB），但麦克风阵列及安装位置、扬声器与回声路径、底盘任务执行器和物理急停接口尚未确定。它们影响模型后端、远场识别和实机动作验收，但不阻塞电脑端接口与模拟链路开发。
