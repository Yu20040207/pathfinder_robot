# 二代机器人第一阶段：ROS 2 视觉与人脸打卡设计

日期：2026-10-04

## 目标与边界

在开发电脑（Ubuntu、ROS 2 Humble、x86_64）上，用安思彊 HP60C 建立可运行的 RGB/深度输入链路，实现人员录入、人脸身份识别和本地打卡。相机以后会装在机器人胸口；软件不依赖当前安装位置。更换相机或迁移到 Jetson 时，应保持视觉输出与打卡数据接口不变。

本阶段不控制底盘、腰部或机械臂。路径规划、到点行驶、电梯按钮定位及按压是后续阶段，不能以本阶段视觉识别结果直接驱动执行器。原仓库的一代 Flask/MQTT、人脸与微控制器代码保留作协议和业务参考；二代代码不直接运行一代应用，也不自动导入仓库中已有的人脸照片、数据库或打卡记录。

## 方案选择

采用独立的 ROS 2 视觉节点和打卡节点，沿用已有的 `ascamera` HP60C 驱动，不修改其厂商 SDK。检测与特征提取先使用 OpenCV YuNet、SFace 的 CPU 推理实现，模型路径、匹配阈值和推理频率均为配置项。系统 OpenCV 4.5.4 虽能构造检测器，却无法实际运行所选 YuNet 2023 模型；视觉节点须在项目虚拟环境中的 OpenCV 4.10.0.84 与 NumPy 1.26.4 下运行，并做真实推理烟测。模型文件采用独立下载脚本及校验值管理，不把模型二进制或个人生物特征数据提交到 Git。模型阈值先采用 OpenCV 官方示例的余弦相似度参考值 0.363，实机录入后须用已知人员与未知人员样本校准，不能把该值当作部署准确率保证。

选择这条路线是为了把相机、识别、打卡和未来动作控制分开。直接包裹旧 Flask/MQTT 应用虽然初期改动较少，但旧视频主题、全局状态和控制消息会进入二代接口，增加后续 ROS 2 导航与机械臂集成成本。一次性引入导航、机械臂和视觉则会在硬件条件未齐时无法完成端到端验收。

## 代码与进程边界

二代项目是当前文件夹中的独立工程；一代仓库只作只读迁移参考，不作为本项目的 Git 历史或远程仓库。二代源码放在 `ros2_ws/src/`。厂商相机驱动工作区在 2026-10-08 位于项目根目录的 `ascam_ros2_ws/`，但整个目录被 `.gitignore` 排除，厂商二进制和第三方 SDK 不属于二代源码。Git 仓库初始化、远程地址与提交留待后续单独处理。

| 单元 | 责任与依赖 | 对外接口 |
| --- | --- | --- |
| `fwr_interfaces` | 定义带时间戳、身份状态、分数、位置和可选距离的类型化消息 | `FaceObservationArray`、`AttendanceEvent` |
| `fwr_data` | 集中管理人员、注册样本和打卡记录，供识别节点和管理界面调用 | SQLite 事务接口与只读人员模板接口 |
| `fwr_vision` 相机启动配置 | 启动或连接 HP60C，映射厂商话题；配置均可覆盖 | 统一的 RGB 图像、深度图、`CameraInfo` 话题 |
| `fwr_vision` 识别节点 | 订阅 RGB，检测人脸、提取特征、与本地注册特征匹配；深度可用且经验证对齐时做距离筛选 | `/robot/vision/faces`；未知人员使用明确的 `unknown` 状态 |
| `fwr_attendance` | 消费稳定的识别结果，执行去重与打卡；提供人员管理界面 | `/robot/attendance/events`；调用 `fwr_data` |
| 本地管理界面 | 仅绑定开发电脑回环地址，录入人员编号与姓名、拍摄或上传多张照片、查看及导出打卡记录、删除人员 | 本地 HTTP 页面；不发布执行器命令 |
| `fwr_bringup` | 启动文件、参数、开发与验收脚本 | 一条命令启动视觉和打卡；可切换相机/录制数据输入 |

界面与节点共享的数据库操作封装在单一模块，SQLite 使用事务与 WAL 模式。运行数据位于用户数据目录，Git 忽略照片、特征、数据库、日志与模型。人员编号唯一；录入图像必须只含一张可用人脸，失败要给出可理解原因。删除人员时同时删除其注册图像和特征，已有打卡记录保留人员编号和当时姓名以供核对。

## 数据流和判定规则

1. 驱动发布 RGB、深度与相机参数；适配启动文件为二代节点提供统一话题。RGB 处理不依赖深度成功启动。
2. 识别节点对 RGB 帧检测人脸并提取特征。无足够相似度者只发布 `unknown`；多个相近候选或图像质量不足时不宣称身份。消息保留采集时间戳，防止旧帧触发新打卡。
3. 深度图先通过时间戳同步。只有验证 RGB 与深度的空间配准后，才按人脸区域计算有效深度中位数并执行可配置距离范围筛选；未验证对齐、缺少深度或像素无效时，距离字段为空且不作基于深度的防伪声明。此版本不实现活体检测，照片或屏幕冒用仍需人工/后续算法处理。
4. 打卡节点要求同一身份在 2 秒窗口内至少 3 次有效识别，再写入一条记录；同一人员 60 秒内重复结果不再次记录。窗口、次数与冷却时间是配置项。无新图像、相机掉线、未知身份或低可信结果均不打卡。
5. 每条记录保存人员编号、当时姓名、设备时间、识别分数和来源设备标识。时间使用带时区的 ISO 8601 格式；页面按本地时区显示。数据库写入失败时保留错误状态并在日志及本地界面提示，不伪造成功事件。

## 验收方式

- 构建并启动二代 ROS 2 包；检查统一 RGB、深度、`CameraInfo` 话题和 `/robot/vision/faces` 的类型与时间戳。
- HP60C 实机接入后验证设备枚举、连续图像、RGB/深度时间同步、相机内参与空间配准；把结果和实际话题记录到项目文档。2026-10-04 已接入并完成初查，但厂商驱动停流，后续项目仍待验收，详见 `docs/hardware/hp60c-validation.md`。
- 用录制图像或测试素材验收：录入人员可识别，未录入者为未知；多人、模糊、无脸、丢帧及相机断开不会误打卡；同一人员重复出现遵守冷却时间。
- 验证录入、删除、查询、CSV 导出及数据库重启持久化。所有测试人脸数据用自备授权素材，不使用一代仓库的人脸照片作默认测试数据。
- 测量开发电脑上的处理帧率与端到端延迟，并记录测试条件；不在未实测前承诺固定性能或准确率。

## 后续阶段接口

第二阶段为底盘驱动、里程计、定位/建图及 Nav2 路径规划；2026-10-05 已开始实现不发运动指令的路径预览。完整导航仍需先拿到底盘运动协议、轮径与轴距、编码器/IMU 数据及安全停车方式。本机当前未安装 Nav2。第三阶段才定义电梯按钮感知、机械臂坐标变换、运动规划、接触反馈及失败回退。腰部更换关节模组时只替换硬件驱动与标定参数，保留上层关节状态和目标接口。迁移 Jetson 时优先替换推理后端与设备启动配置，ROS 2 消息及打卡数据库迁移方案保持独立。
