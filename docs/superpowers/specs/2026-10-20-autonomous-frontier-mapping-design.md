# 实机前沿探索建图与受限倒车设计

日期：2026-10-20

## 目标与边界

操作者在封闭、平整、有人全程看护且能立即切断电机电源的试验区开启自动建图。机器人使用现有 RPLIDAR C1、轮编码器和 DM-IMU-L1 一边建立二维地图，一边自行选择未探索区域；前方出现障碍时先减速或停车，再规划绕行。遇到必须退出的死胡同时，可沿最近实际驶过的轨迹短距离倒车，之后重新规划。完成后保存地图，供 RViz 检查和后续导航使用。

机器人以当前模型和实机 Nav2 参数中的 0.60 m × 0.43 m 底盘外廓为初始占地尺寸，保留现有 0.02 m footprint padding。首次接地试验前仍需用尺核对装配后的最大水平外廓；实物若超出模型，必须先增大 footprint。雷达在车前，车体遮住一部分后方。侧向激光和刚走过的轨迹只能辅助判断，不能证明车尾盲区此刻没有新障碍；首版倒车只在上述看护条件下开放。没有看护的环境保持倒车关闭，待补足车后感知后重新验收。

现有 `real_mapping.launch.py` 已提供 `/scan`、`/imu/data`、`/odom`、`/map` 和 TF，底盘默认关闭运动门。`real_navigation.launch.py` 启动 Nav2 时生命周期默认不激活；`base_bridge` 的普通 `/cmd_vel` 目前拒绝倒车和原地旋转。当前没有自动探索节点、碰撞监测输出链路或自动回退仲裁。键盘建图的短时地面测试已通过，但长期连续运行、动态障碍与自动导航尚未验收。

## 资料依据与路线选择

[Nav2 在线 SLAM 教程](https://docs.nav2.org/rolling/tutorials/general_tutorials/navigation2_with_slam/navigation2_with_slam/)说明可由 SLAM Toolbox 提供 `/map` 与 `map→odom`，同时用 Nav2 执行导航目标。[m-explore-ros2](https://github.com/robo-friends/m-explore-ros2)展示了从已知空地与未知区交界提取 frontier，并按到达代价和信息收益选目标的做法。本项目沿用其算法思路，在现有 ROS 2 接口上加入适合当前底盘的安全门和目标稳定性约束；不直接把第三方探索节点接到电机命令。

固定蛇形轨迹适合边界和宽度已知的矩形区域，不能可靠覆盖首次扫描的房间、走廊与岔路；贴墙行走容易漏掉内部区域。首版选择前沿探索。只有地图边界和场地形状明确后，才考虑用覆盖轨迹补扫局部遗漏。

[Nav2 Collision Monitor](https://docs.nav2.org/rolling/tutorials/general_tutorials/using_collision_monitor/using_collision_monitor/)可在导航控制器与底盘之间按激光区设置减速、停车；其保护区域应覆盖实际外廓及测得的制动距离。[Nav2 BackUp 行为](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/configuring_behavior_server/)提供局部代价图碰撞预测，但标准动作并不记录本车刚走过的曲线路径，因此首版受限回退由独立控制器负责，不能仅开启默认 BackUp 恢复树。

## 节点和命令归属

```text
C1 /scan ────────────────┬→ SLAM Toolbox → /map, map→odom
                         ├→ Nav2 局部/全局代价图
                         └→ Collision Monitor
编码器 + IMU → EKF → /odom, odom→base_footprint
                             │
/map + /odom + 代价图 → 前沿探索器 → NavigateToPose → Nav2 控制器
                                                   │
最近实际行驶轨迹 + 当前代价图 → 受限回退器 ─────────┤
                                    自动命令选择 → Collision Monitor
键盘人工接管 ──────────────────────────────────────────┐   │
                                     底盘桥接单一仲裁/限速 → ESP32
```

底盘桥接仍是 ESP32 串口唯一持有者。桥接分别识别导航、受限回退和人工命令来源，任何时刻只接受一种；人工接管优先停止自动目标。普通 Nav2 `/cmd_vel` 保持禁止负线速度，回退仅通过独立、默认关闭的专用入口，并由桥接再次限制速度、时长和来源。不能通过单纯修改 `forward_only_velocity()` 让所有 Nav2 命令都可倒车。ESP32 的 300 ms 通信超时、故障锁定和上位机的传感器新鲜度/指令超时保持有效；软件不自动清除故障码。

碰撞监测置于自动命令选择器与桥接之间，前进和回退命令都必须经过；普通导航和受限回退不得绕过它直达桥接。监测节点退出、雷达/TF 数据过期、命令链断开时应归零并关闭自动运动门。监测至少有前向停车区和减速区；回退方向也配置可观测区域的停车区，未覆盖的车尾盲区由现场看护承担试验风险，不能标记为传感器已覆盖。区域深度按实测速度、扫描与控制延迟、制动距离及余量确定，配置完成后在 RViz 显示并用实物障碍验证。地图和局部代价图是路径规划依据，近障停车不能只依赖 2 Hz 重规划。

## 探索目标与轨迹

探索器只从机器人可达的已知自由空间搜索 frontier。候选目标落在 frontier 内侧的自由栅格，机器人完整 footprint 加 padding 后不得与占据或未知栅格重叠；局部最窄通道须大于膨胀后的底盘宽度。选择分数综合规划路径长度、到达风险/通道宽度和预计可新增扫描面积。优先保持已选目标，只有目标失效、路径被阻断或收益明显下降才切换，避免左右两条路反复摇摆。失败的目标和附近区域在本次探索中暂时加入黑名单；重复失败达到上限则停机并报告，不无限重试。

使用现有 SLAM Toolbox 在线更新地图、Nav2 低速跟踪与至少 2 Hz 的路径有效性复核。雷达约 10 Hz、局部代价图当前配置 5 Hz；其更新和 Collision Monitor 的停机先于新目标选择。前方障碍出现时先停车/减速，再对当前目标重规划；若绕行不可达，则换另一个 frontier。机器人仅在已确认的自由区域运动，不能为了探索直接穿过未知栅格。地图覆盖完成或无可达 frontier 时停车并保存地图，不自动返回起点或继续巡航。

初期导航前进速度不得超过地面已验证且能持续运行的速度，转弯角速度不得超过 IMU 闭环验证范围；具体持续速度和停距以带载试验结果锁定。现有 Nav2 `desired_linear_vel=0.06 m/s` 与实测底盘起步特性可能不匹配，不能仅依靠配置值推断可行；实车开放前要重复验证长于单次键盘短测的连续前进、缓转与停机。

## 受限倒车与车尾盲区

回退器只在前进路径确实不可达、已停止、最近轨迹连续可信且操作者开启封闭试验模式时进入。它保存带时间戳的最近 `/odom` 轨迹和车体实际扫过的 footprint 走廊，沿轨迹相反顺序追踪，而非向后直冲。初始单段最长 0.10 m、单次累计最长 0.30 m、最多一次回退尝试；速度不超过实车验证的稳定后退速度上限，并设置独立总时限。这些上限只能收紧，扩大须重新设计和试验。

每段开始前要求地图/局部代价图、雷达、IMU、里程计和底盘状态新鲜；整段 footprint 走廊仍为已知自由且留有膨胀余量。左右轮差速可做小幅轨迹修正，IMU 检查实际偏航；不能以一次大角度盲转来探测车后。运动中持续检查局部地图、离轨偏差、编码器进展、故障和超时。出现新障碍、未知栅格、定位跳变、单轮停转、偏航/距离误差超限或车尾看护者急停时立即归零并关闭探索，不自动再次倒车。成功退出后重新让 Nav2 规划前进路线。

“刚走过”只提供候选路径，不是实时安全传感。前置 C1 的车后盲区仍可能有行人、低矮物体或新放置障碍。首轮倒车必须在封闭无人进入的区域由现场人员持续目视车尾、握有立即断电手段；这属于有人看护的试验功能，不能作为开放环境的无人值守避障能力。若场地不能维持这一条件，自动回退入口保持关闭并报告需要人工处理。后续增设经验证的车后测距/碰撞传感并覆盖近场盲区，才可重新评估无人看护的自动倒车。

## 启停与失败处理

自动模式需要显式启动，不随 ROS 节点重启或串口重连自动恢复。启动前检查：只有一套建图/TF 发布者，模型外廓与实物一致，雷达方向正确；`/scan`、`/imu/data`、`/odom`、`/map` 及 TF 时间戳正常；底盘故障码为 0；近障监测链路、Nav2 生命周期和人工停止操作可用；当前区域确实封闭且有人看护。任何条件不满足则保持运动门关闭。

探索完成、操作者停止、键盘接管、导航失败次数达到上限、目标反复左右切换、近障持续触发、地图或定位异常、雷达/IMU/编码器/串口断流、固件故障时取消导航目标，发布零速并关闭自动运动门。停止后不得自动清故障或重启探索；地图先保存为带日期的试验文件，在 RViz 对照真实场地检查墙、门、障碍和轨迹。硬件断电手段始终由现场人员掌握。

## 验收顺序

1. **静态链路**：用不接电机的消息注入验证仲裁、近障停机、传感器过期、导航取消、地图保存以及回退入口默认关闭。核对 RViz 中模型尺寸、雷达视野和车后盲区。
2. **仿真**：在走廊和分岔场景验证 frontier 选择、目标稳定、动态障碍重规划、死胡同回退、未知/占据区域拒绝、人工接管、各类故障停机；记录命令、地图和轨迹。仿真通过不直接等于实机通过。
3. **实车无自动运动**：在现有建图链路中启动 Nav2 与探索器但保持底盘运动门关闭，核对候选 frontier、规划路径、碰撞监测区域、命令归属和停止信号。
4. **封闭场地短测**：有人看护、车尾可见、可立即断电。先验证单个近距离前进目标及障碍前停车、绕行；再单独验证受限 0.10 m 回退，之后才允许一次最多 0.30 m 的完整脱困。每步核对 IMU/编码器、实际位移和停机原因；任何碰撞或失速都停止升级。
5. **小范围探索**：限定首个房间或走廊区段和运行时长，观察目标切换、地图质量与返回路径。完成后停机并保存地图；扩大场地或整机增重后重新验收速度、停距与外廓。

## 实施范围

新增前沿目标选择、最近轨迹记录/受限回退、自动模式状态机与停机诊断；调整实机 Nav2、Collision Monitor、底盘桥接仲裁和启动脚本；保留现有人工键盘和 Gazebo 演示。对前沿选择、狭窄通道、倒车权限、轨迹过期、失速/断流及目标切换设置单元与集成测试。先完成仿真和静态验收，再按上述门槛逐步开放实机运动。
