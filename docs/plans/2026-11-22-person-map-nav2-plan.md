# 人在 map 系的定位 + Nav2 跟随导航：可行性与实施方案

> 2026-11-22 起草。关联：`docs/remote-control-v1.0.md`（跟随/视觉现状）、`AGENTS.md` §3 视觉与跟随段。
> 状态：**方案待用户确认**，未写任何生产代码。

## 0. 一句话结论

**可行，但不能"用 Nav2 换掉现在的跟随"**。正确形态是**双模式**：

- 人近（≤1.5 m，画面里看得见）→ 现在这套 20 Hz 视觉伺服（`person_follower`，已有 65 单测 + 22 场景）；
- 人远了 / 绕到障碍后面 / 出了房间 → 用 map 系的人位置 + Nav2 规划避障过去，到了再切回视觉伺服。

真正的难点就是你说的那个：**人在 map 系的坐标**。它 = 车的位姿（AMCL）× 人的相对位置（相机方位 + 雷达/深度距离）。

## 2. 人在 map 系：三种实现

### 2.1 雷达腿 + 相机方位（推荐先做，TF 齐、无标定依赖）

- 相机（YOLO 框中心）→ **方位角** θ，精度足够（640 宽、HFOV≈70° → 0.11°/px）；
- 在 θ ± 8° 内取 `/scan_merged` 点做 1D 聚类，取宽度 **0.05~0.55 m** 的簇当作"腿/小腿"，
  簇质心 → 人的水平位置；两腿都看到就取中点；
- 雷达到人中心的距离误差 ~0.1 m（角度分辨率 0.25° → 3 m 处 1.3 cm，腿面估计误差为主）；
- `laser_front` 在 **0.075 m 高**，只扫到小腿 → 桌腿/椅腿会混进来，靠"YOLO 方位窗 + 连续 3 帧同一簇"过滤。

**优点**：TF 现成，今天就能验证。**缺点**：低矮家具误检、厚裤腿/裙摆时簇变宽。

### 2.2 深度取框内距离（更直接，但要先补 TF）

- 框的下半部（髋~腿，y ∈ [0.55h, 0.95h]）取深度**中位数**（剔 0 值，要求有效像素 ≥30%）；
- 用 `camera_info` 的 fx/fy/cx/cy 反投影成 3D 点 → TF 到 map；
- 优点：直接得到人（躯干+腿）的位置，不依赖"腿宽"启发式；缺点：需要相机安装位（x,y,z,俯仰）+ 深度远处/深色衣物失效（HP60C 有效距离约 0.3~3 m）。

### 2.3 融合 + 卡尔曼（最终形态）

- map 系匀速卡尔曼，状态 `[x, y, vx, vy]`，10 Hz 更新，两个观测源按协方差加权；
- **预测** 0.3~0.5 s（补偿检测+规划延迟）→ 这才是你说的"预测人的位置"；
- 人丢 2 s 内用预测外推（画面上标"预测位置"），超 2 s 判丢失、停/降级。

## 3. Nav2 怎么接（分三个 Phase，风险递增）

### Phase 1（建议先上）："到人最后出现的位置"

- 跟随时人丢失 > 2 s → 用**最后可信的人位姿**（map 系，含 0.5 s 预测）生成 standoff 目标：
  沿"人→车"方向退 **1.2 m**（落在已知自由格，否则 0.5 m 内就近吸附）；
- 一次性 `NavigateToPose`（`xy_goal_tolerance 0.4`，`max_vel 0.25`）；
- 到达 → 停 → 恢复视觉跟随（人应该就在眼前）；仍看不到 → 原地小范围转身找人（现有 `search` 逻辑）。
- 这一步**不需要 1 Hz 持续追踪**，风险最小，能覆盖"人走远了/绕个弯"的 80% 场景。

### Phase 2：持续目标更新

- 1 Hz 用 `NavigateToPose` 的 **goal handle update**（不是 cancel+resend）更新目标；
- 人或预测点位移 > 0.5 m 才重发；
- 处理"人自己就是障碍"：人腿进 `obstacle_layer` 会让目标变 lethal → standoff 保持 1.2 m；必要时把人的簇从该帧 scan 里剔除（进阶，先不做）。

### Phase 3：模式仲裁（两条速度通道不能同时说话）

```
距离 < 1.5 m 且画面里有人  → 视觉伺服（20 Hz，现有 follow_core）
距离 ≥ 1.5 m 或 人不可见   → Nav2 规划（/cmd_vel_auto_safe）
```
切换必须**先发 0 速度再切**，并打日志（`模式切换：伺服→Nav2，原因=人距 2.4 m`），否则两条链路抢底盘。

## 4. 难点与风险（按优先级）

1. **AMCL 位姿误差 = 人的位置误差**。长走廊/开阔区雷达特征少时 AMCL 会飘几十厘米。对策：人位姿带协方差；AMCL 跳变 >0.3 m 时重置滤波器；地图上再测 3 个已知点当标尺。
2. **`allow_unknown: false`**：人站在没建过图的区域 → 规划直接失败。对策：目标吸附到最近已知自由格；吸附失败 → 降到"开到边界 + 视觉跟随"。
3. **腿误检（桌/椅/宠物）**：对策 = YOLO 方位窗 + 时间一致性 + 尺寸窗。
4. **膨胀半径 0.48 会吃掉 standoff 点**：窄门口/角落可能把 1.2 m 的 standoff 落到膨胀区（老问题：goal 被吸附 0.34 m）。对策：standoff 沿多角度试 5 个候选点，取 cost 最低且可达的。
5. **速度差**：人走 0.8~1.2 m/s，Nav2 现在 0.15~0.25 m/s → 纯 Nav2 永远追不上，**必须"近了切伺服"**。
6. **相机 TF 缺失**：深度方案的前置条件。要实测相机安装位（`base_link` 到镜头光心的 x/y/z + 俯仰角），补 URDF 或 `static_transform_publisher`。
7. **安全**：`motion_enabled` / `manual_enabled` 仍由用户开；`collision_monitor`、`front_stop`、`rear_guard` 全保留；人离车 <0.8 m 一律停。

## 5. 里程碑与验收标准

| 里程碑 | 内容 | 工时 | 验收（可测的数字） |
| --- | --- | --- | --- |
| M0 | 补 `base_link→camera_link` TF（实测安装位）+ 核对内参 | 0.5 d | `tf2_echo base_link camera_link` 有稳定输出 |
| M1 | `person_localizer` 节点（§2.1 雷达腿，深度作为可选第二源）+ 单测 | 1~1.5 d | 人站 1.0/2.0/3.0 m（卷尺）、偏离中线 ±0.5 m 共 6 个点，map 系位置误差 **≤0.30 m** |
| M2 | `person_goal` 节点（Phase 1）+ 假 map/TF 黑盒（domain 42） | 1.5~2 d | 人站 4 m 外房间 → 车自行规划到 1.2 m 内停；路上有椅子能绕 |
| M3 | Phase 2 持续更新 + 模式仲裁 + 日志 | 1~2 d | 人走动时目标 1 Hz 跟随，不出现两条通道抢速（日志可查） |
| M4 | 现场调参 + 文档 | 1 d | 一次完整演示：客厅跟随 → 人进卧室 → 车规划过去 → 切回伺服 |

**合计 5~7 个工作日**（含实机调参）。M1 结束就能回答"人的位置准不准"，M2 结束就知道整条链路可不可用。

## 6. 明确不建议的做法

- ❌ 用 Nav2 做近距离跟随（1 Hz 重规划 + 0.25 m/s 上限，必然一卡一卡，还不如现在的 20 Hz 伺服）。
- ❌ 指望 Nav2 把"人"当动态障碍去绕/去追 —— Nav2 只会躲障碍，不会追障碍。
- ❌ 为了"追上人"直接把 `manual_max_speed_mps` 提到 0.6 —— 先看 Nav2 0.25 能不能到；提底盘上限是另一件事，需要单独批准。
- ❌ 让两条通道同时发速度 —— 必须先 0 速度再切。
